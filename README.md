# DomainUp — Selectel DDNS

Интерактивная установка автоматического обновления домашнего IPv4 в Selectel DNS actual. Версия **2.0.0**.

Запускаешь `install.sh`, отвечаешь на вопросы — установщик ставит зависимости, проверяет доступ к Selectel, сохраняет конфигурацию и включает службу с таймером. После этого хост сам проверяет внешний IP каждые две минуты, в том числе после перезагрузки.

## Запуск

Склонируйте репозиторий или скачайте и распакуйте [архив](https://github.com/Xellan/domainup/archive/refs/heads/main.zip):

```bash
git clone https://github.com/Xellan/domainup.git
cd domainup
sudo bash install.sh
```

Если уже работаете от `root`, достаточно `bash install.sh`. Запускайте из интерактивного терминала на машине хомлаба.

Автоустановка зависимостей поддерживает **Debian/Ubuntu (apt)** и **Fedora/RHEL с dnf**. Требуется уже работающий systemd версии **247+**; установщик проверяет это до установки пакетов. Он ставит Python 3, корневые сертификаты, `dig` и `curl`, затем проверяет Python **3.9+**. Если штатные пакеты слишком старые, потребуется обновление ОС. Python-библиотеки через pip не нужны.

## Что спросит установщик

1. Номер аккаунта Selectel.
2. Имя проекта с DNS-зоной.
3. Имя сервисного пользователя и пароль; пароль не отображается при вводе.
4. Доменную зону, например `example.com`.
5. Номер A-записи из списка, полученного через API Selectel.
6. Подтверждение установки и запуска после успешной проверки.

В список попадают группы с одним активным A-адресом, которыми не управляет другой ресурс. Запись должна уже существовать в Selectel. Если подходящих записей нет, создайте A-запись в панели и запустите установку снова.

Перед заменой существующей установки скрипт проверяет конфигурацию и API. При установке он сохраняет предыдущие файлы в `/var/lib/selectel-ddns/backups/`, записывает новые файлы, запускает настоящую службу через systemd и только после её успешного завершения включает таймер. При ошибке установки восстанавливает прежние файлы и состояние таймера. Установленные системные зависимости при отмене или откате сохраняются. Если первый запуск уже обновил DNS, откат локальных файлов это изменение не отменяет.

## Подготовка Selectel и сети

Создайте [сервисного пользователя](https://docs.selectel.ru/access-control/manage/add-user/) с ролью `member` **в проекте DNS-зоны**. Эта роль даёт доступ к ресурсам выбранного проекта. Установщик использует его имя и пароль для получения проектного IAM-токена; вручную создавать или продлевать токен не требуется. [Аутентификация API](https://docs.selectel.ru/api/authorization/).

DNS-зона должна быть делегирована на актуальные NS Selectel: `a.ns.selectel.ru`, `b.ns.selectel.ru`, `c.ns.selectel.ru`, `d.ns.selectel.ru`. Регистрация домена сама по себе этого не гарантирует. [Проверка делегирования](https://docs.selectel.ru/dns-hosting/records/check-records/).

Пример:

```text
home.example.com.  A      <публичный IPv4 дома>
app.example.com.   CNAME  home.example.com.
```

Можно обновлять A-запись самого `example.com`, если поддомены ссылаются на него. CNAME меняются только при изменении вашей схемы DNS, а при смене IP достаточно обновить выбранную A-запись.

WAN IPv4 роутера должен совпадать с внешним IPv4 этого хоста. При CGNAT автоматическое обновление DNS не обеспечивает входящий доступ. Хост должен выходить в интернет через домашний роутер: VPN может изменить обнаруженный адрес. Проверьте проброс портов и отсутствие устаревших AAAA-записей у основного имени и сервисных поддоменов.

## Обновление существующей установки

В каталоге клонированного репозитория:

```bash
git pull --ff-only
sudo bash install.sh
```

Установщик найдёт `/etc/selectel-ddns/config.json` и предложит использовать текущие настройки. Чтобы поменять проект, пароль или запись, ответьте «нет» и заполните поля; Enter сохраняет предложенное значение, в том числе существующий пароль. Установка из предыдущего пакета 1.x обновляется той же командой. Копировать или переименовывать `config.example.json` вручную не нужно.

## Работа службы

`selectel-ddns.service` выполняет одну проверку; `selectel-ddns.timer` запускает её примерно каждые две минуты. После успешной проверки служба становится `inactive (dead)` — это нормально. Таймер остаётся включённым. Он также запускает проверку после загрузки хоста.

```bash
systemctl list-timers --all selectel-ddns.timer
journalctl -u selectel-ddns.service -n 30 --no-pager
```

При совпадении IP запрос изменения DNS не отправляется. При смене адреса скрипт обновляет только выбранную A-группу и устанавливает TTL **60 секунд**. Если IP не менялся, а TTL был выше 60, скрипт сообщает об этом; TTL можно заранее снизить в панели Selectel. Резолверы могут сохранять прежний адрес до истечения старого TTL. [DNS API v2](https://docs.selectel.ru/api/dns-actual/).

Ошибки сети и API попадают в журнал; следующая попытка будет по таймеру. При обрыве соединения после PATCH сервер мог успеть обновить запись — следующий запуск перечитает её фактическое значение.

Проверка без изменения DNS:

```bash
sudo python3 /usr/local/lib/selectel-ddns/selectel-ddns.py --config /etc/selectel-ddns/config.json --check
```

Ручной рабочий запуск:

```bash
sudo systemctl start selectel-ddns.service
```

Проверка DNS — замените имя на своё:

```bash
dig @a.ns.selectel.ru home.example.com A +noall +answer
```

Конфигурация хранится у root с правами `0600` в каталоге `0700`. Systemd передаёт её службе через `LoadCredential`, а процесс работает с `DynamicUser=yes`. Пароль не хранится в аргументах команд и не выводится в журнал. [Systemd credentials](https://systemd.io/CREDENTIALS/).

Коды выхода скрипта: `0` — успешная проверка/обновление, `1` — ошибка сети/API или состояния DNS, `2` — ошибка конфигурации. `--check` возвращает `0`, даже если обнаружено необходимое обновление: фактической записи в этом режиме нет.

## Остановка

```bash
sudo systemctl disable --now selectel-ddns.timer
sudo systemctl stop selectel-ddns.service
```

## Проверки разработки

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
bash -n install.sh
systemd-analyze verify selectel-ddns.service selectel-ddns.timer
```

Тесты используют имитацию HTTP, package manager и systemctl. Они проверяют обновление DNS, ошибки, скрытие паролей, установку, повторную установку и откат. Реальные пакеты и службы на тестовой машине не меняются.
